# securitygen

`securitygen` generates a Go implementation of an [ogen](https://github.com/ogen-go/ogen)
`SecurityHandler`. It is intended for use from `go generate` in another Go
module.

The generator supports API key, HTTP Basic, HTTP Bearer, and OAuth2 handlers.
It emits an implementation, its dependency interfaces, and helpers for placing
the authenticated identity in `context.Context`.

> **Security note:** this is an adapter generator, not a complete
> authentication system. Your application must implement the generated store
> and verifier interfaces, securely validate passwords and tokens, enforce its
> own issuer/audience and key-management rules, and protect credentials from
> logs and telemetry.

## Quick start

Requirements:

- Go 1.25 or newer
- an API package generated by [ogen](https://github.com/ogen-go/ogen)

First generate or update the ogen API package from your OpenAPI document. Then
place a `go:generate` directive in the package that should contain the handler:

```go
package security

//go:generate go run github.com/b-sn/ogen-sec/cmd/securitygen@v0.1.0 -source ../api/oas_security_gen.go -output security.go -api-import example.com/project/internal/api -package security -type Handler -constructor NewHandler
```

Run it after every ogen generation:

```sh
go generate ./internal/security
```

`security.go` is generated output and is replaced in full on every run; do not
edit it manually. The example is pinned to the current release, `v0.1.0`.
Use a newer release tag or a reviewed commit when upgrading this dependency.

If the OpenAPI document has no security schemes, ogen does not emit
`oas_security_gen.go`; there is no `securitygen` invocation to run.

## Supported handlers

`securitygen` recognizes credential types by their fields, rather than security
scheme or method names:

| Handler | ogen credential fields | Generated dependency |
| --- | --- | --- |
| API key | `APIKey string`, optional `Roles []string` | `APIKeyStore` |
| HTTP Basic | `Username string`, `Password string`, optional `Roles []string` | `BasicAuthStore`, `PasswordVerifier` |
| HTTP Bearer | `Token string`, optional `Roles []string` | `BearerTokenVerifier` |
| OAuth2 | `Token string`, `Scopes []string` | `OAuth2TokenVerifier` |

Constructor dependencies are included only for schemes present in the ogen
`SecurityHandler`, in this stable order: API key, Basic auth, Bearer, OAuth2.
For example, an API with all four kinds produces:

```go
handler := security.NewHandler(apiKeys, basicAuth, passwords, bearerTokens, oauth2Tokens)
```

The generated dependency interfaces are deliberately application-owned. For
example, `APIKeyStore` receives a SHA-256 hash rather than the raw key, and a
Bearer or OAuth2 verifier is responsible for returning only trusted identity
data. Read the generated interface comments before implementing them.

Methods whose credential shape is not supported remain explicit
`panic("<method>: not implemented")` stubs. Treat those as a deployment blocker:
implement the method yourself or do not route requests to it.

## Command options

Required:

- `-source`: Go file declaring `SecurityHandler`, normally ogen's `oas_security_gen.go`
- `-output`: destination generated Go file
- `-api-import`: import path of the package containing `SecurityHandler` and its credential types

Optional:

- `-package`: destination package name; default `security`
- `-type`: generated struct name; default `passthroughSecurityHandler`
- `-constructor`: constructor name; default `NewPassthroughSecurityHandler`

The generator parses the source package directly and does not require the API
package to build first. It also reads active non-test Go files from that package
to resolve credential declarations such as ogen's `oas_schemas_gen.go`.

## Compatibility and upgrades

The repository's compatibility suite is pinned to ogen `v1.24.0`. A new ogen
release may change the generated `SecurityHandler` or credential shapes. When
upgrading it, update `OGEN_VERSION` in the Makefile, run `make check`, review
the integration golden diff, and refresh it only after accepting the change:

```sh
UPDATE_GOLDEN=1 make test
```

## Development

The integration fixtures test the full path from OpenAPI to ogen, then through
`securitygen`, and finally compile the generated result in an isolated module.
`ogen` and `golangci-lint` are pinned binaries in `./bin`, not dependencies of
this module.

```sh
make test             # install ogen locally and run all tests
make lint             # install and run golangci-lint
make schema-validate  # validate every OpenAPI fixture through ogen
make ogen             # generate SCHEMA into OGEN_TARGET (and use OGEN_CONFIG)
make check            # lint and test
```
